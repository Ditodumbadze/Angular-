Angular გზამკვლევი

Angular აპლიკაციის სწავლა იწყება დღეს აქ

ინტერპოლაცია არის Angular-ის ერთ-ერთი ძირითადი მახასიათებელი, რომელიც საშუალებას გაძლევთ მონაცემები (data) დინამიურად გამოაჩინოთ HTML შაბლონებში (templates). ის მარტივად და ეფექტურად აკავშირებს კომპონენტის თვისებებსა და ცვლადებს HTML ელემენტებთან.

ინტერპოლაციისთვის გამოიყენება ორმაგი ფიგურული ფრჩხილების სინტაქსი {{ variableName }}. მაგალითად, თუ კომპონენტში გვაქვს მომხმარებლის სახელი, მისი გამოსატანად HTML-ში ჩავწერთ:

5 HTML Template 
<h1>მოგესალმებით, {{  username }}</h1>

ამ მაგალითში, username ცვლადის მნიშვნელობა ავტომატურად ჩაენაცვლება HTML ტექსტს.

ინტერპოლაციით ასევე შეგიძლიათ გამოიძახოთ კომპონენტის მეთოდები (ფუნქციები):

5 HTML Template 
<h2>{{  getWelcomeMessage() }}</h2>

ამ დროს getWelcomeMessage() ფუნქცია შესრულდება და მისი დაბრუნებული (returned) მნიშვნელობა გამოჩნდება ეკრანზე.

შეჯამება: ინტერპოლაცია Angular-ის Data Binding-ის ფუნდამენტური ნაწილია, რომელიც აპლიკაციას დინამიურს, სუფთას და ინტერაქტიულს ხდის.

Reference Variable არის გზა, რომლითაც HTML-ის შიგნით შეგიძლია შექმნა "მინიშნება" (ცვლადი) რომელიმე HTML ელემენტზე (მაგალითად: <input>, <video>, <form> ან სხვა) და შემდეგ ეს ელემენტი ან მისი მნიშვნელობა პირდაპირ გამოიყენო შენს კოდში.

მას ვქმნით ჰეშის (hash) სიმბოლოთი # (ან სიტყვით ref-).

პრაქტიკული მაგალითი: წარმოიდგინე, გაქვს საძიებო ველი (<input>) და ღილაკი. გინდა, რომ როდესაც მომხმარებელი ღილაკს დააჭერს, წაიღო იმპუტში ჩწერილი ტექსტი და კონსოლში დაბეჭდო.

5 HTML Template (app.component.html) 
<div style="padding: 20px;">  <!-- #myInput არის ჩვენი Reference Variable -->  <input type="text" #myInput placeholder="ჩაწერე რამე...">    <!-- ღილაკზე დაჭერისას ვგზავნით იმპუტის მთელ ობიექტს ან მის მნიშვნელობას (.value) -->  <button (click)="showInputVal(myInput.value)">ტექსტის წამოღება</button></div>

რა მოხდა აქ? #myInput ემაგრება ზუსტად ამ <input> ელემენტს. ამის მერე HTML-ის ფარგლებში ჩვენ შეგვიძლია მივწვდეთ ამ იმპუტის ნებისმიერ თვისებას (მაგალითად, .value გვაძლევს იმპუტში ჩაწერილ ტექსტს).

TS TypeScript (app.component.ts)

როგორ შევამოწმოთ ეს ბრაუზერის DevTools-ით?
როდესაც ამ კოდს გაუშვებ და ბრაუზერში გახსნი აპლიკაციას:

1. Console ტაბის გამოყენება: ჩაწერე რამე ტექსტი იმპუტში და დააჭირე ღილაკს. გახსენი ბრაუზერის Console (F12 -> Console) და დაინახავ, რომ იქ ზუსტად დაიბეჭდა ის სიტყვა, რაც ინპუტში იყო. ეს ნიშნავს, რომ Reference Variable-მა წარმატებით "დაიჭირა" იმპუტის მნიშვნელობა და გადასცა TypeScript ფუნქციას.

2. Elements ტაბი: გადადი Elements ტაბზე და შეხედე იმ <input> ელემენტს. დააკვირდი, რომ Angular ამ #myInput მითითებას ბრაუზერში უბრალო, სტანდარტულ HTML-ად ატარებს, თავად კი შიდა მექანიზმით მართავს კავშირებს.

შეჯამება: Reference Variable არის მარტივი და ძლიერი მექანიზმი Angular-ში, რომელიც საშუალებას გაძლევთ პირდაპირ დაუკავშიროთ HTML შაბლონის ელემენტები კომპონენტის ლოგიკას ზედმეტი სირთულეების გარეშე.

რა არის Null-Safe Navigation და რატომ გვჭირდება?
როდესაც Angular აპლიკაციას წერ, მონაცემების დიდ ნაწილს სერვერიდან (API-დან) იღებ ასინქრონულად. ეს ნიშნავს, რომ აპლიკაციის ჩატვირთვის პირველ წამებში ზოგიერთი ობიექტი შესაძლოა იყოს null ან undefined (ანუ ცარიელი).

თუ შენ HTML-ში პირდაპირ დაწერ ასეთ რამეს: <p>{{ user.name }}</p>, და იმ მომენტში user ობიექტი არ არსებობს (ცარიელია), ბრაუზერი გამოიტანს შეცდომას (Error) და მთელი გვერდი გაითიშება.

იმისათვის, რომ ეს არ მოხდეს, ვიყენებთ Null-Safe Navigation ოპერატორს (?.): <p>{{ user?.name }}</p>.

რას შვება ის? ის ამოწმებს: თუ user ობიექტი არსებობს, წაიკითხე მისი name, ხოლო თუ user ჯერ არ არის (ცარიელია), უბრალოდ არაფერს გამოიტანს და კოდი არ გაფუჭდება.

პრაქტიკული მაგალითი: როგორ დავწეროთ კოდი. წარმოიდგინე, რომ გვყავს კომპონენტი, სადაც მომხმარებლის მონაცემები თავიდან არ გვაქვს (არის null) და გარკვეული დროის შემდეგ იტვირთება.

TS TypeScript (app.component.ts)

5 HTML Template (app.component.html) 
<div style="padding: 20px;">  <button (click)="loadUserData()">მონაცემების ჩატვირთვა</button>  <!-- უსაფრთხო ნავიგაციის გამოყენება -->  <h2>მომხმარებლის სახელი: {{ user?.name }}</h2>  <p>ელ-ფოსტა: {{ user?.email }}</p></div>

როგორ შევამოწმოთ ეს ბრაუზერის DevTools-ით?
როდესაც ამ კოდს გაუშვებ და ბრაუზერში გახსნი აპლიკაციას:

1. თავდაპირველი მდგომარეობა (როცა user არის null): გახსენი Console (F12 -> Console). დააკვირდი, რომ ეკრანზე სახელი და ელ-ფოსტა უბრალოდ ცარიელია, მაგრამ კონსოლში არანაირი წითელი შეცდომა არ იძებნება. ეს იმის დამსახურებაა, რომ ?.-მა თავიდან აგვაცილა კრახი.

2. მონაცემების ჩატვირთვა: დააჭირე ღილაკს "მონაცემების ჩატვირთვა". 2 წამის შემდეგ, როგორც კი setTimeout იმუშავებს და user ობიექტი შეივსება, ეკრანზე ავტომატურად გამოჩნდება სახელი (ნინო) და მეილი.

3. რა მოხდებოდა ოპერატორის (?.) გარეშე? თუ კოდში user?.name-ის ნაცვლად დაწერდი user.name-ს, თავიდანვე Console-ში მიიღებდი ასეთ შეცდომას: TypeError: Cannot read properties of null (reading 'name'). ეს ყველაზე ხშირი შეცდომაა დამწყებ დეველოპერებში და ?. არის მისი მთავარი მკურნალი!

შეჯამება: Null-Safe Navigation ოპერატორი (?.) არის კრიტიკული ინსტრუმენტი Angular-ში, რომელიც გიცავს აპლიკაციის (Crashes) გათისვისგან და უზრუნველყოფს სტაბილურობას ასინქრონული მონაცემების მართვისას.

სტრუქტურული დირექტივები (ან ახალი ჩაშენებული ბლოკები) პასუხისმგებელია იმაზე, რომ შეცვალონ HTML-ის სტრუქტურა — ანუ დაამატონ, წაშალონ ან გაანაწილონ ელემენტები ეკრანზე იმის მიხედვით, თუ რა პირობა ან მონაცემები გვაქვს.

Angular-ის თანამედროვე ვერსიებში გამოიყენება სრულიად ახალი, სუფთა და სინტაქსურად მოსახერხებელი მიდგომა: @if, @for და @switch. ძველი *ngIf და *ngFor სინტაქსი უკვე წარსულს ბარდება.

1. @if — ელემენტის პირობითი გამოტანა (Conditional Rendering)
თუ გინდა, რომ რაიმე ელემენტი (მაგალითად, გაფრთხილება, ღილაკი ან მთელი ბლოკი) გამოჩნდეს მხოლოდ მაშინ, როცა კონკრეტული პირობა ჭეშმარიტია (true), ვიყენებთ @if ბლოკს.

TS TypeScript (app.component.ts) 
import { Component } from '@angular/core';@Component({  selector: 'app-root',  templateUrl: './app.component.html'})export class AppComponent {  isLoggedIn = false; // თავიდან მომხმარებელი არ არის შესული  // ღილაკზე დაჭერისას ვცვლით სტატუსს საპირისპიროდ  toggleLogin() {    this.isLoggedIn = !this.isLoggedIn;  }}

<div style="padding: 20px;">  <button (click)="toggleLogin()">    {{ isLoggedIn ? 2. @for — სიების და მასივების გამოტანა (List Rendering)
როდესაც გაქვს მონაცემთა მასივი (მაგალითად, პროდუქტების, მომხმარებლების ან დავალებების სია) და გინდა თითოეული მათგანისთვის HTML ელემენტის გენერირება, ვიყენებთ @for ბლოკს. თანამედროვე Angular-ში სავალდებულოა track მითითება, რომელიც ეხმარება ბრაუზერს სიის ეფექტურად მართვაში.

3. @switch — მრავალმხრივი პირობითი გამოტანა (Selection Rendering)
როდესაც გაქვს რამდენიმე ურთიერთგამომრიცხავი პირობა (მაგალითად, მომხმარებლის როლი შეიძლება იყოს: admin, editor ან guest), @switch ბლოკი გვეხმარება კოდის სუფთად და ორგანიზებულად დაწერაში. ის აფასებს ცვლადს და იმის მიხედვით, თუ რომელი მნიშვნელობა აქვს მას, გამოიტანს შესაბამის @case ბლოკს. თუ არცერთი ქეისი არ დაემთხვა, ამოქმედდება @default ბლოკი.

როგორ შევამოწმოთ ეს ბრაუზერის DevTools-ით?

1. Elements ტაბის ძალა: გახსენი აპლიკაცია და ჩართე Inspect -> Elements. დააკვირდი HTML ხეს: როდესაც isLoggedIn არის false, @if ბლოკის შიგნით არსებული div ფიზიკურად არ არსებობს DOM-ში. დააჭირე ღილაკს "შესვლა", რომ გახდეს true — ის წამიერად გაჩნდება ბრაუზერში.

DOM-შიც მხოლოდ ეს ერთი div იარსებებს. დააჭირე ღილაკს "გახდი ადმინი" და დააკვირდი Elements ხეს: წინა ბლოკი ფიზიკურად გაქრება DOM-დან და მის ადგილას მყისიერად გაჩნდება ადმინისტრატორის წითელი ჩარჩოიანი div. @switch ყოველთვის ტოვებს DOM-ში მხოლოდ იმ ელემენტს, რომლის ქეისიც ამჟამად აქტიურია.

4. Angular DevTools გამოყენება: გახსენი ბრაუზერის ინსტრუმენტებში Angular ტაბი. იპოვე AppComponent კომპონენტი. იქ დაინახავ შენს ცვლადს — userRole. როდესაც ღილაკს აჭერ, დააკვირდი, როგორ იცვლება მისი მნიშვნელობა ('guest'-დან 'admin'-ზე ან 'editor'-ზე) და როგორ რეაგირებს ამაზე ინტერფეისი.

შეჯამება: კონტროლის ახალი ნაკადი (Control Flow: @if, @for და @switch) ხდის Angular შაბლონებს სუფთას, ბევრად უფრო სწრაფს და ადვილად წასაკითხს ძველ დირექტივებთან შედარებით.

წარმოიდგინე სიტუაცია: გაქვს HTML კოდის რაღაც ნაწილი (მაგალითად, ბარათის დიზაინი, ცხრილის უჯრა ან ღილაკი), რომელიც გვერდზე რამდენიმე ადგილას მეორდება, მაგრამ შიგნით განსხვავებული მონაცემები უნდა ჩაჯდეს, ან გინდა, რომ კოდი არ გააორმაგო (DRY პრინციპი — Don't Repeat Yourself). სწორედ ამისთვის არსებობს ngTemplateOutlet.

1. ჯერ ქმნი შაბლონს <ng-template> ტეგით (რომელიც თავისთავად ეკრანზე არ ჩანს და ბრაუზერში არ იხატება).

შეჯამება: ngTemplateOutlet არის Angular-ის ძლიერი მექანიზმი შაბლონების მრავალჯერადი გამოყენებისა და დინამიური UI კომპონენტების შესაქმნელად.

• ტრადიციული პრობლემა: თუ track-ს არ მივუთითებთ, სიაში თუნდაც ერთი ელემენტის დამატებისას ან წაშლისას, ბრაუზერს შეიძლება მოხდეს მთელი სიის თავიდან დახატვა (Re-rendering), რაც ტყუილად ტვირთავს მეხსიერებას და ანელებს აპლიკაციას.

ეს არის საუკეთესო გზა იმის სანახავად, თუ როგორ ზოგავს track რესურსებს:

1. Elements ტაბი და DOM-ის ციმციმი (F12 -> Elements): გახსენი აპლიკაცია ბრაუზერში და ჩართე ელემენტების ინსპექტირება (Elements). დააკვირდი <ul> სიას და მის შიგნით არსებულ <li> ტეგებს. დააჭირე ღილაკს "დავალების დამატება თავში". დააკვირდი Elements ხეს: დაინახავ, რომ ახალი li ელემენტი უბრალოდ ჩაჯდა სიის სათავეში, ხოლო ძველი ელემენტები ფიზიკურად არ განადგურებულან და თავიდან არ დახატულან — Angular-მა ისინი უბრალოდ გადააადგილა (Move), რადგან track task.id-ით მიხვდა, რომ ესენი ზუსტად იგივე ძველი ელემენტებია.

2. რა მოხდებოდა track-ის გარეშე? ძველ სინტაქსში (*ngFor და trackBy ფუნქციის არარსებობისას) სიის თავში ელემენტის დამატება გამოიწვევდა მთელი სიის (ყველა li-ს) წაშლას და თავიდან გენერაციას, რაც ბრაუზერისთვის დამატებითი რესურსია.

შეჯამება: track მექანიზმი @for ბლოკში არის კრიტიკული ინსტრუმენტი აპლიკაციის წარმადობის (Performance) ასამაღლებლად და DOM-ის უსარგებლო განახლებების თავიდან ასაცილებლად.

ეს არის Angular-ის არქიტექტურის გული და ფუნდამენტი — Angular Components (კომპონენტები). ყველაფერი Angular-ში შედგება კომპონენტებისგან.

რა არის Angular Component?
მარტივად რომ ვთქვათ, კომპონენტი არის აპლიკაციის ერთი დამოუკიდებელი, თვითმმართველობადი ნაწილი (ბლოკი), რომელიც პასუხისმგებელია ეკრანის კონკრეტული ნაწილის გამოჩენასა და ლოგიკაზე. მაგალითად: ნავიგაციის პანელი (Navbar), პროდუქტის ბარათი, ფორმა ან მთლიანი გვერდი — თითოეული მათგანი ცალკეული კომპონენტია.

თანამედროვე Angular-ში (მათ შორის შენს მიერ არჩეულ 21.2.0 ვერსიაში) გამოიყენება Standalone Components არქიტექტურა. თითოეული კომპონენტი შედგება სამი ძირითადი ნაწილისგან:

1. TypeScript კლასი (.ts) — შეიცავს ლოგიკას, ცვლადებს და ფუნქციებს.
2. HTML შაბლონი (template) — განსაზღვრავს როგორ გამოიყურება ეკრანი.
3. Decorator (@Component) — აკავშირებს მათ ერთმანეთთან და ეუბნება Angular-ს, თუ რა სახელით (selector) უნდა მიმართოს ამ კომპონენტს HTML-ში.

პრაქტიკული მაგალითი: როგორ შევქმნათ და გამოვიყენოთ კომპონენტი. მოდი, შევქმნათ მარტივი შვილობილი კომპონენტი სახელად HelloComponent და ჩავსვათ ის მთავარ AppComponent-ში.

როგორ შევამოწმოთ ეს ბრაუზერის DevTools-ით?
კომპონენტების არქიტექტურის შესამოწმებლად ბრაუზერის ინსტრუმენტები შეუცვლელია:

1. Elements ტაბი (F12 -> Elements): გახსენი აპლიკაცია ბრაუზერში და ჩართე ელემენტების ინსპექტირება. დააკვირდი HTML სტრუქტურას: შენ დაინახავ სრულიად ჩვეულებრივ ტეგს <app-hello></app-hello>, რომლის შიგნითაც სრულად არის გენერირებული იმ კომპონენტის HTML შიგთავსი. Angular ამ გზით აწყობს აპლიკაციას კომპონენტების "აგურ-აგურ".

2. Angular DevTools ტაბი: გახსენი ბრაუზერის ინსტრუმენტებში Angular ტაბი. მარცხენა მხარეს დაინახავ შენი კომპონენტების იერარქიულ ხეს (Component Tree): თავშია AppComponent, ხოლო მის შიგნით — HelloComponent. დააკლიკე HelloComponent-ს და მარჯვენა მხარეს დაინახავ მის შიდა ცვლადებს (მაგალითად, username: "გიორგი"). აქედან შეგიძლია რეალურ დროში ადევნო თვალი კომპონენტების მდგომარეობას.

შეჯამება: Components წარმოადგენს Angular აპლიკაციის აგურებს — თითოეული კომპონენტი აერთიანებს თავის თავში შაბლონს, სტილსა და ლოგიკას, რაც უზრუნველყოფს კოდის მოდულურობასა და სისუფთავეს.

მარტივად რომ ვთქვათ, Data Binding არის ხიდი ანუ საკომუნიკაციო არხი შენს TypeScript (ლოგიკასა და ცვლადებს) და HTML (ვიზუალურ ნაწილს) შორის. იმის ნაცვლად, რომ ხელით წერდე კოდს იმისათვის, რომ ბრაუზერში ტექსტი ან ღილაკის მდგომარეობა შეიცვალოს, Angular-ის Data Binding ამას ავტომატურად აკეთებს. როცა ცვლადი იცვლება TypeScript-ში, ეკრანიც ავტომატურად ახლდება (და პირიქით).

Angular-ში Data Binding იყოფა რამდენიმე ძირითად მიმართულებად:

1. One-Way Binding (ერთმიმართულებიანი ბაინდინგი):
• Component-დან HTML-ისკენ:
- Interpolation ({{ }}): მონაცემების ტექსტად გამოტანა.
- Property Binding ([property]): ელემენტის თვისებების (მაგალითად: ღილაკის disabled, სურათის src, იმპუტის value) მართვა.
• HTML-დან Component-ისკენ:
- Event Binding ((event)): მომხმარებლის ქმედებაზე (კლიკი, აკრეფა) რეაგირება.

2. Two-Way Binding (ორმხრივი ბაინდინგი):
- ([(ngModel)]): მუშაობს ორივე მიმართულებით ერთდროულად. თუ მომხმარებელი იმპუტში ტექსტს ჩაწერს, TypeScript ცვლადიც ავტომატურად იცვლება და პირიქით.

პრაქტიკული მაგალითი: მოდი, ერთ კომპონენტში გავაერთიანოთ Property Binding და Two-Way Binding, რომ თვალსაჩინოდ ვნახოთ როგორ მუშაობს ეს სისტემა.

როგორ შევამოწმოთ ეს ბრაუზერის DevTools-ით?
Data Binding-ის მუშაობის შესამოწმებლად ბრაუზერის ინსტრუმენტები საუკეთესო დამხმარეა:

1. Elements ტაბი (F12 -> Elements): გახსენი აპლიკაცია და ჩართე Elements ინსპექტირება. დააკვირდი <img [src]="imageLink"> ტეგს: ბრაუზერში ის გამოჩნდება როგორც სუფთა src="https://...". დააკვირდი ღილაკს: დააჭირე ღილაკს, რომ isDisabled გახდეს true. შეხედე HTML ხეს — დაინახავ, რომ ღილაკს მყისიერად დაემატა ატრიბუტი disabled="". ეს Property Binding-ის პირდაპირი შედეგია.

2. Two-Way Binding-ის რეალურ დროში ტესტირება: ჩაწერე რამე ახალი ტექსტი იმპუტში ([(ngModel)]). დააკვირდი იმავდროულად ორ რამეს: პირველი — ინტერპოლაციის ტექსტი ქვემოთ მყისიერად იცვლება; მეორე — თუ გახსნი Angular DevTools ტაბს ბრაუზერში და შეხედავ AppComponent-ის პროპერტიებს, დაინახავ, რომ username ცვლადის მნიშვნელობაც ზუსტად იმ წამსვე იცვლება, როგორც კი კლავიატურიდან სიმბოლოს აკრეფ. ორმხრივი კავშირი სრულად მუშაობს!

შეჯამება: Data Binding არის ავტომატური და ელეგანტური ხიდი TypeScript-სა და HTML-ს შორის, რომელიც უზრუნველყოფს მონაცემთა ორმხრივ და ერთმიმართულებიან სინქრონიზაციას.

მარტივად რომ ვთქვათ, Directive არის ინსტრუქცია Angular-ისთვის, რომელიც ეუბნება მას, თუ როგორ უნდა შეცვალოს ან მართოს HTML ელემენტის ქცევა, გარეგნობა ან სტრუქტურა DOM-ში.

Angular-ში არსებობს დირექტივების სამი ძირითადი ტიპი:

1. Components (კომპონენტები): დირექტივები, რომლებსაც აქვთ საკუთარი HTML შაბლონი (Template).
2. Attribute Directives (ატრიბუტ-დირექტივები): ცვლიან არსებული ელემენტის ვიზუალს, სტილს ან ქცევას (მაგალითად: ngClass, ngStyle, ან ჩვენ მიერ შექმნილი custom დირექტივები).
3. Structural Directives (სტრუქტურული დირექტივები): ცვლიან DOM-ის სტრუქტურას — ამატებენ ან შლიან ელემენტებს (მაგალითად: @if, @for, @switch).

პრაქტიკული მაგალითი: ngClass და ngStyle გამოყენება. ჩაშენებული ატრიბუტ-დირექტივები საშუალებას გვაძლევს, რომ HTML ელემენტს კლასები ან CSS სტილები დინამიკურად მივანიჭოთ პირობების მიხედვით.

შეჯამება: Conditional Rendering ბლოკები (@if / @else if / @else) უზრუნველყოფენ DOM-ის ელემენტების დინამიურ და ეფექტურ მართვას პირობების მიხედვით.

სიები (Lists) და მონაცემთა მასივების ვიზუალიზაცია ნებისმიერი თანამედროვე ვებ-აპლიკაციის ფუნდამენტია (იქნება ეს პროდუქტების კატალოგი, ამოცანების სია, თუ მომხმარებელთა ცხრილი).

Angular-ში სიებთან მუშაობა წარმოუდგენლად ძლიერი და მარტივია თანამედროვე Control Flow (@for) მექანიზმის წყალობით:

1. track სავალდებულო მექანიზმი: ეხმარება ბრაუზერს, ზუსტად იცოდეს რომელი ელემენტია რომელი, რათა რესურსები ტუილად არ დაიხარჯოს.
2. @empty ბლოკი: ავტომატურად ამუშავებს სიის ცარიელ მდგომარეობას (თუ მასივი ცარიელია, რა გამოჩნდეს ეკრანზე).
3. შიდა კონტექსტური ცვლადები (Implicit Variables): @for ციკლს ავტომატურად აქვს ჩაშენებული მახასიათებლები:
- $index — ელემენტის ინდექსი (0, 1, 2...).
- $even / $odd — ლუწი ან კენტ ნომერზეა თუ არა ელემენტი (ძალიან მოსახერხებელია ზებრული დიზაინისთვის — Zebra Striping).
- $first / $last — არის თუ არა ელემენტი სიის დასაწყისი ან ბოლო.

პრაქტიკული მაგალითი: სრული სია კონტექსტური ცვლადებით. შევქმნათ პროდუქტების სია, სადაც თითოეულ ელემენტს ექნება თავისი ნომერი ($index), ლუწი/კენტი ფონი ($even/​$odd) და ვნახოთ რა მოხდება, თუ სია ცარიელი იქნება.

რა არის Reactive Forms და რატომ გვჭირდება?
Reactive Forms გაძლევს საშუალებას, რომ ფორმის ლოგიკა, მონაცემები და ვალიდაცია (შემოწმება) პირდაპირ TypeScript კოდში განსაზღვრო, რაც კოდს სტრუქტურირებულს, ტესტირებადს და კონტროლირებადს ხდის.

მისი ძირითადი ცნებებია:
1. FormGroup — მთლიანი ფორმა (ან ფორმის ჯგუფი), რომელიც აერთიანებს ცალკეულ ველებს.
2. FormControl — ფორმის ცალკეული ველი (მაგალითად, სახელი ან მეილი), რომელიც აკონტროლებს მის მნიშვნელობას და სტატუსს.
3. Validators — წესები (ვალიდაცია), რომლებიც ამოწმებენ, არის თუ არა ველი შევსებული სწორად (მაგალითად: სავალდებულოა, მინიმალური სიმბოლოების რაოდენობა, მეილის ფორმატი და ა.შ.).

პრაქტიკული მაგალითი: მარტივი სარეგისტრაციო ფორმა. მოდი, ავაწყოთ ფორმა, რომელსაც ექნება ორი ველი (სახელი და ელ-ფოსტა) თავისი ვალიდაციებით და გაგზავნის ღილაკი, რომელიც ჩაიკეტება (disabled), სანამ ფორმა არასწორადაა შევსებული.

• Service (სერვისი): არის ცალკე TypeScript კლასი, რომლის ერთადერთი მიზანია ბიზნეს-ლოგიკის შენახვა, მონაცემების დამუშავება ან სერვერთან კომუნიკაცია. სერვისი არ ეხება ვიზუალურ მხარეს (HTML-ს), ის მხოლოდ მონაცემებით და ლოგიკით არის დაკავებული.

რა არის Angular HttpClient და როგორ მუშაობს?
HttpClient არის Angular-ის ჩაშენებული სერვისი, რომელიც საშუალებას გვაძლევს გავაგზავნოთ HTTP მოთხოვნები (GET, POST, PUT, DELETE და ა.შ.) და მივიღოთ პასუხები.

თანამედროვე Angular-ში HttpClient-ის გამოსაყენებლად საჭიროა ორი ძირითადი ნაბიჯი:
1. კონფიგურაცია (app.config.ts): აპლიკაციას უნდა ვუთხრათ, რომ ვიყენებთ HTTP კლიენტს provideHttpClient() ფუნქციით.
2. RxJS Observable: HttpClient-ის მოთხოვნები აბრუნებენ Observable ობიექტს, რომელსაც უნდა "მოვუსმინოთ" (.subscribe()), რომ მონაცემები მივიღოთ.

პრაქტიკული მაგალითი: მონაცემების წამოღება საჯარო API-დან. გამოვიყენოთ უფასო ტესტური API (JSONPlaceholder) და წამოვოღოთ მომხმარებლების სია რეალური სერვერიდან.

რა არის Signal და რატომ არის ის ასეთი მაგარი?

1. რა არის Signal? Signal არის "ჭკვიანი ცვლადი", რომელიც ფლობს მნიშვნელობას და თავად ატყობინებს ყველას (მათ შორის UI-ს), როცა მისი მნიშვნელობა იცვლება.
2. Fine-grained Reactivity (წვრილმარცვლოვანი რეაქტიულობა): როცა Signal იცვლება, Angular-ს აღარ სჭირდება მთელი კომპონენტის ან ხის თავიდან დათვალიერება. ის ზუსტად იმ ერთადერთ ადგილს ანახლებს HTML-ში, სადაც ეს Signal გამოიყენება.
3. სამი ძირითადი ინსტრუმენტი:
- signal() — ვქმნით ცვლადს საწყისი მნიშვნელობით.
- computed() — ვქმნით წარმოებულ ცვლადს, რომელიც ავტომატურად ითვლის მნიშვნელობას სხვა სიგნალებზე დაყრდნობით.
- effect() — ავტომატურად რთდება ყოველ ჯერზე, როცა მის შიგნით გამოყენებული რომელიმე სიგნალი იცვლება.

Network სიაში დააჭირე შესაბამის მოთხოვნას და გადადი Headers ტაბზე. განყოფილებაში Request Headers დაინახავ, რომ ინტერცეპტორმა ავტომატურად ჩაამატა authorization: Bearer my-super-secret-jwt-token-98765 ხაზი ყოველგვარი დამატებითი ძალისხმევის გარეშე.

შეჯამება: HTTP Interceptors (ფუნქციური ინტერცეპტორები) უზრუნველყოფს მოთხოვნებისა და პასუხების ცენტრალიზებულ და ავტომატურ დამუშავებას ფონურ რეჟიმში.

იმისათვის, რომ სრულად გავიაზროთ ეს თემა, შევადროთ ერთმანეთს ორი მიდგომა: Client-Side Rendering (CSR) და Server-Side Rendering (SSR).

1. Client-Side Rendering (CSR - ტრადიციული SPA): როდესაც მომხმარებელი ხსნის საიტს, ბრაუზერი იღებს ცარიელ HTML ფაილს, სადაც მხოლოდ <app-root></app-root> წერია. ბრაუზერი ტვირთავს JavaScript ფაილებს და აწყობს გვერდს. მინუსი: პირველი ჩატვირთვა ნელია და SEO-სთვის რთული.
2. Server-Side Rendering (SSR): აპლიკაცია ჯერ სერვერზე (მაგალითად Node.js გარემოში) ეშვება და სრულად აწყობს HTML გვერდს. ბრაუზერი იღებს უკვე მზა, დასრულებულ HTML-ს, რომელიც მყისიერად ჩნდება ეკრანზე (იდეალურია სისწრაფისა და SEO-სთვის).

რა არის Hydration (ჰიდრატაცია)?
